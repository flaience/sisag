# Read model da prontidão da agenda

O read model reúne, com escopo obrigatório de empresa, unidade, serviço e profissional, os fatos necessários ao checklist de prontidão.

Ele considera vínculos ativos, duração específica do profissional quando existente, períodos de atendimento, regras ativas de distribuição aplicáveis ao serviço e exceções ativas. A saída contém somente o checklist sanitizado, alertas e o indicador somente leitura; não expõe linhas, nomes ou dados pessoais.

Esta etapa ainda não publica API nem interface e não altera configurações.
